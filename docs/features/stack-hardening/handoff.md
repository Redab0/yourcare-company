## Behavior and contract

- `--dart-define=API_ENV=development` selects the DEV API and matching chat origin and displays a DEV ribbon, including release builds. Only `production` and `development` are accepted; existing commands still default to production.
- Secure credentials and local caches use a `development_` namespace in DEV. Existing production keys remain compatible; logout clears only the selected environment. Old unnamespaced development credentials are deliberately not migrated because their environment cannot be established safely.
- `stack_contract.dart` defines strict order states and service types. Existing outgoing status serializers use the canonical order values where compatible. Endpoint-specific payment/offer/history/display aliases remain intact. No booking, price, money, timezone or payment lifecycle change is intended.
- Shared Dio generates/preserves bounded `X-Request-ID` values. Its replacement diagnostic interceptor records static operation category, method, status and request ID only, never headers, body, query values, URLs or personal content. Flutter and platform error hooks feed a bounded 50-record diagnostic adapter. Debug Flutter's own error presenter remains available.
- Multipart uploads remain on the existing endpoint. Local checks reject more than 10 files, images over 20 MiB, videos over 100 MiB or aggregate files over 100 MiB before constructing multipart payloads. The backend is authoritative; direct upload is additive and has not been adopted here.

## Firebase and native isolation

These checkouts have production Firebase project files only. DEV skips Firebase initialization, token registration, Remote Config network access, Analytics and Crashlytics collection. Remote Config exposes local defaults. Android's DEV manifest removes FirebaseInitProvider and hard-deactivates Analytics; native collection and messaging auto-init default off. The final iOS build phase removes GoogleService-Info.plist from the generated DEV app only, preserving the source file and restoring it for production builds. Firebase behavior tests and bundle-script tests cover the branches.

Production initializes Firebase normally, explicitly enables collection when `TELEMETRY_ENABLED=true` (default), tags release/environment and records redacted error type/stack plus static journey API outcome events. `TELEMETRY_ENABLED=false` turns collection off and deletes unsent crash reports. Android Crashlytics symbol upload requires both production and explicit `-PCRASHLYTICS_UPLOAD_SYMBOLS=true`; no symbol upload occurred in DEV builds. Dashboard delivery, native crash symbolication and on-device push remain unverified.

The native application IDs are unchanged. These are DEV test artifacts, not independently provisioned Firebase flavors: use a dedicated test install/device. A separate DEV Firebase project and native application identities require actual project files/provisioning before enabling push or remote telemetry in DEV. No credentials were invented.

Verified both platform artifacts: iOS app has no GoogleService-Info.plist, disabled collection flags, DEV API URL and no production API URL; merged Android release manifest has no FirebaseInitProvider and includes Analytics deactivation.
